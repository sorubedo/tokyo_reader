# 书库存储采用「书库目录」抽象，替换 Hive 且不做迁移

应用原先用 Hive 把整本书库序列化为单一 JSON key 存储在 Web 端，而原版 `hive` 已停更，且目标已变为多平台与本地文件夹书库，因此决定重构存储层：书库呈现为一个统一的书库目录抽象——每本书以稳定 ID 命名的书籍文件保存在目录中，根目录的元数据索引登记全部书籍元数据；桌面端用 `fs_shim`（dart:io 真实目录）+ `dir_picker` 选择目录，Web 端用 `fs_shim` 的 OPFS 实现并回退 IndexedDB，Android 落地时用 `saf` 包实现 SAF 适配器。原 Hive 依赖与数据直接移除，不做迁移，因为项目仍处早期、没有已发布用户数据需要保留。

## Considered Options

- **hive_ce**：维护活跃、API 兼容，但仍是键值模型，不符合文件夹书库的设计目标，未采用。
- **dbas_filesystem**：功能丰富且活跃，但 Web 仅支持 OPFS、围绕应用私有目录设计，与用户可选书库目录冲突，未采用。
- **Hive 数据迁移**：项目早期且无已发布用户，为一次性数据写迁移代码不值得，未采用。

## Consequences

- 书籍元数据与书籍内容分离，整库不再在每次写入时序列化全部正文。
- 内容指纹（大小 + 修改时间 + SHA-256）用于检测外部修改；v1 仅更新指纹并标记状态，不校验进度与书签。
- Android 的 SAF 读写需要独立的 `LibraryStorage` 实现（基于 `saf` 包），在 Android 平台真正落地时补充。
